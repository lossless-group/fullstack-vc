## Why Care?

A public profile is how a member shows up on the hub: on the people page, with the tools they actually use, counted on each tool's page, and linking out to their own LinkedIn and site. Members could always switch it on themselves from the profile editor. Since May, that switch saved without error and changed nothing.

## What's New?

- **The switch works.** Sign in, open your profile editor, switch on "Make my profile public" and save. You're on the [people page](/people) on the next load, and switching it off takes you off just as fast.
- **The editor remembers.** It opens with the setting you last saved, not the one in the site's files.

## What Happened

The switch shipped on April 28, when saving the editor committed your profile file straight to the site's repository through a GitHub App. On May 21, stacks moved to Turso to stop that one-commit-per-save churn, and the GitHub App write path was retired. The save endpoint kept accepting the public flag, for compatibility with the editor, but nothing wrote it anywhere. No error, no change.

## Under the Hood

The fix follows the same shape stacks already use: Turso holds what members edit, and the markdown is a snapshot.

- **A `ProfileVisibility` table** in Turso, one row per member who has saved the switch. It's created on first use, so no schema migration was needed. No row means the profile's markdown decides, which keeps every operator-made profile working as before.
- **The save endpoint writes it.** `/api/stack/save` stores `publish` again whenever the editor sends it.
- **Pages read it first.** The profile page, the editor and the people page all take the saved choice over the markdown. The people page is now rendered per request instead of at build time, so a change shows on the next load, not the next deploy.
- **The snapshot catches up.** `pnpm sync:stacks:turso` now writes each saved choice into the profile's `publish:` line. A member who has only changed their visibility keeps their markdown stack exactly as it is; the script won't rebuild a stack from Turso for someone who has none there.

Tested end to end against a local database: switching a profile private took it off the people page and showed the private placeholder; switching it back restored both.

The editor still requires that your profile's handle matches your GitHub login. Members whose profiles were set up by hand under a different handle can ask to have it switched on for them.
