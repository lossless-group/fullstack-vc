## Why Care?

The hub had grown past the point where you could find things by clicking around. Seventy-odd tools, two dozen fellows, recipes, sessions, projects: you had to already know where something lived.

Now there's a search bar at the top of every page. Type "personal agent" and you get the session, the tools and the people who use them, with the matching words highlighted. Pick a tag or two and the results narrow to things that carry *all* of them.

Behind it, the registry caught up with the conversation. The Dojo's group chat has been comparing personal agents, terminal multiplexers, model gateways and agent-native CRMs for weeks; the tools they keep naming now have pages, and the fellows who use them have those tools on their stacks.

## What's New?

- **Site-wide search.** A spill-out palette in the header covers tools, recipes, sessions, published people, projects and working groups. "Show" chips filter by kind; tag chips stack, and stacked tags must *all* match. Arrow keys move, Enter jumps, Backspace removes the last tag.
- **A filterable catalogue.** [All tools](/stacks/see-all-tools/) gains a filter bar: text plus stackable tags, with counts that recount as you narrow. It shares state with the header, so tags picked in the palette arrive already selected, and the `?q=&tags=` URL reopens the same view.
- **41 new tools**, each with a banner and icon saved on the site:
  - **Personal agents:** Instinct, Meta's Muse, Grok Bot, Patricia by HyperPerfect, Claude Cowork, Muesli.
  - **Agent-native multiplexers:** Herdr, Rex (Superlogical), TuiOS, plus Omarchy, NixOS, Hyprland and Arch Linux.
  - **Model gateways:** OpenRouter, Concentrate.ai and Requesty, joining TrustedRouter.
  - **CRM and GTM:** Twenty, Affinity, HubSpot, Linear, Cargo, Clay, lemlist, Connect The Dots, SOAR Connect.
  - **Coding and browser agents:** OpenAI Codex, Devin, Claude in Chrome, Playwright, Chrome DevTools MCP, Replit.
  - **And more:** ChatGPT, Kimi, DeepSeek, Google Vertex AI, Osaurus, Wispr Flow, OneDrive, Context.dev, event-hog, and AI Rob (Rob Snyder's GTM method sold as a Claude skill).
- **Stacks updated from the chat.** 69 person-tool mappings, sorted into current, want-to-try and dropped, across 17 fellows. Ten fellows who posted but had no profile now have one, kept private.
- **Better images.** Eleven tools whose banners didn't render now ship real og:images saved locally, or a homepage screenshot where the site publishes none.
- **Profiles can show a website** next to LinkedIn.

## How it Works

Some of the hub's pages render on demand, so there's no complete set of built HTML for [Pagefind](https://pagefind.app/) to crawl. Instead the build prerenders `/search-records.json`, one record per listed page, each carrying two filters:

```
kind  →  Tool · Recipe · Session · Person · Project · Working Group
tag   →  the registry's tags; a person carries the tags of the tools they use
```

Then `scripts/build-search-index.mjs` feeds those records to Pagefind's Node API and writes the index next to the static output. The browser fetches index fragments on demand, so a query costs a few kilobytes rather than the whole catalogue. Tags use Pagefind's `all` operator, which is what makes them narrow rather than widen. The whole pattern is ported from [lossless-toolkit-site](https://github.com/lossless-group/lossless-toolkit-site), where it searches about 1,900 tools.

The header palette and the catalogue filter are separate Svelte islands, but they import one module-level `$state` object, so they share a single selection without events or navigation.

## Under the Hood

**The stack sync's sharp edge.** Turso is the source of truth for some fellows' stacks, and `sync:stacks:turso` rewrites a fellow's whole markdown stack from it. Most fellows have never signed in and have no Turso rows: their markdown *is* the record. Adding even one Turso row for them would have made the next sync wipe everything else. So only the three Turso-backed stacks went through `add:stack:turso`; the rest were edited in markdown. No accounts were pre-created, because sign-in keys on the roster email and a guessed row would duplicate the moment someone logs in.

**Privacy.** The chat is private. Public tool pages describe what "a Dojo member" reported, without names. Profile stacks list tools only; the notes saying who said what stayed out of the repo. A draft post that quotes fellows by name is held back until they've agreed to it.

**Two missing dependencies.** `@libsql/client` was only resolving by accident of pnpm hoisting, so `pnpm add:stack:turso` couldn't run at all; it's now declared. `pagefind` is a new dev dependency, and `pnpm build` now indexes after `astro build`.

**Dev mode.** `pnpm search:dev`, run while `pnpm dev` is up, builds the index into a gitignored `public/pagefind/` so search works without a production build.
